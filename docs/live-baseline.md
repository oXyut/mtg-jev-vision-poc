# 実写真2枚の初回baseline（2026-10-19）

画像付き実APIで認証・推論が成功した。一方、盤面・整列とも1枠を採用した後、2回目の低Box確信で停止した。遮蔽あり盤面の8枚検出・8名同定という最低ラインは未達である。Issue #11で探索の問題を追跡し、位置検出は #1、同定は #2と関連付ける。

## 固定条件

- 評価したコード: `81f6ec5da1eb439b1dba8e9ca83296f217ee9dc7`（PR #10の統合branch）。
- `jev-1.14.0`、固定`https://api.typesafe.ai/v1/systemone`、`TypeSafe-Danger-Zone-Images: true`。HTTPS proxyとNetwork secretを利用し、redirect・自動retryなし。
- 2写真ともEXIF向き反映後1536×1152px。メタデータを持たない新規RGB画像からPNGを生成した。
- `max_cards=12`、各写真`max_requests=14`、`presence_yes=0.8`、`presence_no=0.2`、`min_box_confidence=0.6`、`duplicate_iou=0.85`。正解枚数で上限を決めていない。
- 正解名・枚数・枠・限定候補を推論へ与えず、写真間で予測を渡していない。推論中は採点ディレクトリの読取りを禁止した。両予測を保存・確定後に採点した。
- 手動の可視部分AABBを実行前に固定。印刷されたカードの見える断片全体を囲み、青いスリーブを除く。ダイスで外側の辺を推測せず、隠れた全体枠は評価しない。写真端はclipする。遮蔽辺は数pxの注記付き。
- 一対一最大個数対応をIoU 0.50／0.75で別集計。実行後に閾値・枠規則を変更していない。

## 名前同定と原因の切分け

採用枠の名前は両方ともunknown。一般カタログは未取得、日本語Tesseract言語データは未導入（engは利用可能）で、OCR→カタログ同定の実写真精度は未測定。これは日本語認識が失敗した実測ではなく、依存とカタログが揃わず未実行という意味である。

現行Jev要求は名前を求めず、検出処理はunknownを返す。直接Jevによる名前同定は未実装であり、OCR方式との精度比較も実行していない。正解8名だけの候補集合や人間の推測で成功扱いしていない。

確定した停止要因は、未報告カードの在否を高く返した2回目のBox確信が、固定閾値0.6を下回ったこと。整列でも同じ停止が起きており、遮蔽・回転・反射だけを原因と断定できない。既報告boxをstateで除外する反復探索、対象指定、実験的Box機能のどこに問題があるかは未確定である。通信失敗・認証失敗ではない。

## 費用・安全性・検証

旧環境は0回／US$0のまま。初回baselineは失敗・retryなしの計4回、入力20,417／出力144 token、文書記載の入力100万tokenあたりUS$0.042で計算した推定US$0.000857514。全呼出しでusageを取得した。請求明細による確定額ではない。承認枠は全体30回／US$1で、初回終了時点の残りは26回／推定US$0.999142486だった。その後の[分割追試](partition-experiment.md)で26回を使い、累計30回／推定US$0.003473862に達したためAPIを停止した。課金設定は変更していない。

各呼出し前に共有ledgerへ試行を記録し、費用不明の失敗があれば以後の実呼出しを停止する実験手順を用いた。公開CLI単独の各実行は累積予算を自動共有しないため、追加実験にも実験全体のledgerが必要である。

`python3 -m unittest discover -s tests -v`: オフライン56件成功。推論コード・閾値は変更していない。写真、crop、正解名対応、EXIF、個別枠座標、API本文、内部Library情報は公開しない。詳細表・可視化・個別記録はユーザー専用成果物に保存する。
